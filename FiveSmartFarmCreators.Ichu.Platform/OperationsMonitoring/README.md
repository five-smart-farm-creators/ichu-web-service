# Operations and Monitoring

This module is the core domain of ICHU. It receives the telemetry that Edge Gateways synchronize, keeps the alerts evaluated at the edge with their stable identities, records attention, field events and clinical interventions, and publishes thresholds and geofences to the gateways. It implements the backend side of US-13, US-14, US-15, US-16, US-17, US-19, US-21, US-22, US-23, TS-06, TS-07, TS-08, TS-09 and the monitoring part of TS-15 and TS-18 from the Report.

The collar always transmits over BLE to the Portable Edge Gateway; the collar never calls this API. The gateway evaluates thresholds and geofences locally and later synchronizes readings, alerts and alert changes. The central API therefore never creates alerts from client requests and never lets an application choose a severity.

## Conventions

- JSON uses camelCase. Enumerations are strings and are parsed case-insensitively, so `PENDING` and `Pending` are equivalent; responses use PascalCase values.
- Identifiers are Guid UUIDs. Reading identity is `deviceId` + `readingId` as generated by the firmware (TS-01); alert identity is the `alertId` generated by the gateway; field operations and alert changes are identified by the client-generated `operationId`.
- Timestamps are ISO 8601 `DateTimeOffset` values stored in UTC. `recordedAt` is the capture time and `receivedAt` the central reception time. Periods are half-open: `from` included, `to` excluded.
- Units: body temperature `celsius`, activity `index`, rumination `minutes`, battery `percent`, positions in decimal degrees, accuracy and distances in meters, durations in seconds.
- A measurement has `status` Valid, Invalid or Absent. Only a valid measurement has a value; absence is never reported as zero or as a normal state.
- Errors are ProblemDetails: 400 invalid input, 401 missing identity or gateway credentials, 403 denied access, 404 unknown reference, 409 conflict or duplicate identity with different content.

## Public API

User routes require an authenticated request (`[Authorize]` with the host's default scheme) and a server-side ranch decision from `IMonitoringAccessControl`. Gateway routes are anonymous for user authentication and are authorized by `IEdgeGatewayAuthenticator` instead.

| Method | Route | Caller and permission | Behavior |
| --- | --- | --- | --- |
| POST | `/api/v1/telemetry/batch` | Edge Gateway | TS-06/TS-07. Body `readings`, `alerts`, `alertChanges` (1 to 500 entries). Returns 200 with one result per entry: `kind`, `id`, `status` (Accepted, Duplicate, Rejected, Conflict), `reason`, `relatedAlertId`. |
| GET | `/api/v1/animals/{animalId}/telemetry?from&to&page&pageSize` | ReadMonitoring | TS-08/US-14. Readings ordered by capture time, `totalCount`, and `oldestRetainedRecordedAt`. An empty range returns an empty collection. Page size 1 to 500, default 100. |
| GET | `/api/v1/animals/{animalId}/telemetry/latest` | ReadMonitoring | US-13. Latest valid value of each indicator and the `lastKnownPosition`, each with `recordedAt` and `isStale` (older than 24 hours), or `Unavailable`. |
| GET | `/api/v1/alerts?ranchId&status&animalId&page&pageSize` | ReadMonitoring | TS-09. Alerts newest event first, with origin, severity, event time, version and supporting reading identifiers. |
| PATCH | `/api/v1/alerts/{alertId}` | AttendAlerts | TS-09/US-19. Body `status=Acknowledged`, `finding`, `action`, `operationId`, `expectedVersion`. 200 when applied or when the same operation is repeated; 409 with the current alert for a stale version or a different operation. |
| PUT | `/api/v1/monitoring-thresholds` | ManageRules | Creates or replaces the range for `ranchId`, `lifeStage`, `metric` (BodyTemperature, ActivityIndex), `minValue`, `maxValue`, `severity`. |
| GET | `/api/v1/monitoring-thresholds?ranchId` | ReadMonitoring | Thresholds of the ranch. |
| POST | `/api/v1/geofences` | ManageRules | US-15. `ranchId`, `lotId`, `name`, `toleranceMeters`, `severity`, `vertices` (3 to 500, closed simple polygon). One geofence per lot; 409 if the lot already has one. |
| PUT | `/api/v1/geofences/{geofenceId}` | ManageRules | Replaces name, tolerance, severity and boundary. |
| GET | `/api/v1/geofences?ranchId` | ReadMonitoring | Geofences of the ranch with ordered vertices. |
| GET | `/api/v1/edge-gateways/{gatewayId}/monitoring-rules?afterRevision` | Edge Gateway (own id only) | Full thresholds and geofences of the gateway's ranch when its revision is newer, otherwise 304. |
| POST | `/api/v1/field-events` | RecordFieldEvents | US-21. `operationId`, `animalId`, `type` (HealthEvent, Birth), `occurredAt`, `observation`. 201 created, 200 repeated, 409 different content or inactive animal. Missing fields are listed together. |
| POST | `/api/v1/clinical-interventions` | RecordClinicalInterventions | US-23. `type` (Vaccination, Treatment, Insemination), `product`, `dose`, plus the field-event values. |
| POST | `/api/v1/mobile-sync/batch` | Same as each operation | TS-18. `operations` (1 to 500) with an individual result per operation. |
| GET | `/api/v1/animals/{animalId}/livestock-operations?from&to` | ReadMonitoring | Field events and interventions of the animal. |

### Edge batch entries

- Reading: `readingId`, `deviceId`, `recordedAt`, and optional `bodyTemperature`, `activityIndex`, `ruminationMinutes`, `batteryLevel` as `{ value }` or `{ invalidReason }`, plus `position` as `{ latitude, longitude, accuracyMeters }` or `{ invalidReason }`.
- Alert: `alertId`, `deviceId`, `type` (Temperature, Activity, Geofence), `severity` (Informative, Warning, Critical), `readingIds` (the first is the triggering reading), `configurationRevision`, `thresholdMinValue` and `thresholdMaxValue` for threshold alerts, or `geofenceId` and `distanceToBoundaryMeters` for geofence alerts.
- Alert change: `operationId`, `alertId`, `kind` (Evidence, Cleared, Acknowledged), with `deviceId` and `readingIds` for evidence, `occurredAt` for a return or attention, and `authorId`, `finding`, `action`, `expectedVersion` for attention.

Readings are processed before alerts and alerts before changes, so one batch may contain an alert and its evidence. Each entry is saved independently.

## Domain rules

- A repeated identifier with identical content is a duplicate; with different content it is a conflict and the original is kept (TS-04, TS-07).
- A reading is attributed to the animal whose device assignment was effective at capture time. Without an assignment the reading is kept as device data and excluded from herd projections. Later releases or reassignments do not change the attribution.
- A capture time ahead of the server clock beyond `OperationsMonitoring:ClockSkewTolerance` (default 5 minutes) is rejected. Late arrivals from offline operation are never rejected for their delay.
- A reading is rejected when the device is unknown, belongs to another ranch, or its assigned animal was not active at capture time. Negative activity or rumination, battery outside 0 to 100, invalid coordinates and values that are both present and marked invalid are rejected.
- An alert is raised at the capture time of its triggering reading. Every supporting reading must belong to the same animal and, for threshold alerts, have a valid measurement outside the threshold sent by the gateway; geofence evidence requires a valid position. The configuration revision must have been published for the ranch. An animal that was not active at that time does not generate alerts.
- A new alert of the same type and animal within six hours of an open alert joins it as evidence and returns Duplicate with `relatedAlertId`, keeping the open alert's identity (US-16, TS-05). Acknowledged or cleared alerts are no longer open.
- Attention requires a finding and the current version. Response time is measured from the event time to the attention time; Edge attention keeps its own event time and the cloud uses its request time. Repeating an operation returns the original result without changing its time (US-19).
- A geofence alert records the return to the permitted area once, and its exit duration (US-17).
- Thresholds and geofences are configured by each ranch; ICHU supplies no default clinical ranges. Every change advances the ranch rule revision, and gateways receive a consistent snapshot read in one repeatable-read transaction.
- A field operation is rejected for missing fields, unknown animals and missing permission, and is a conflict when the animal was not active when it occurred (US-22). Product and dose are accepted only for clinical interventions.

## Cross-context contract

`IOperationsMonitoringContextFacade` (Interfaces/Acl) is the read contract for other modules. It performs no user authorization; callers authorize the ranch or animal first.

| Method | Consumer | Result |
| --- | --- | --- |
| `GetReadingsAsync(ranchId, from, to, ct)` | DashboardAnalytics | Readings attributed to animals, with null for invalid or absent metrics. |
| `GetAlertsAsync(ranchId, from, to, ct)` | DashboardAnalytics | Alerts raised before `to` and not acknowledged before `from`, with type, severity, raise, acknowledgement and clearance times. |
| `GetLastDeviceCommunicationAsync(deviceId, ct)` | IoTAssets (US-11) | Latest capture and reception times and the battery level of that reading, or null. |
| `GetLivestockOperationsAsync(cattleId, from, to, ct)` | Planning, CattleInformation | Field events and interventions with product and dose. |

These records are proposals pending integration review. DashboardAnalytics currently defines its own `IAnalyticsSource` port on an unmerged branch; its adapter should map these records without querying monitoring tables.

## Ports required from the host

The module defines minimal ports instead of referencing other modules. None has a production implementation in this branch, and `AddOperationsMonitoring` registers no permissive or empty fallback, so the host fails to resolve the services until real adapters are registered.

| Port | Owner of the data | Required behavior |
| --- | --- | --- |
| `IMonitoringAccessControl` | Iam (Diego) | Verified current account and a per-request decision for ReadMonitoring, AttendAlerts, RecordFieldEvents, RecordClinicalInterventions and ManageRules. A mapping to IAM scopes (Read, ClinicalWrite, Manage) and to field-operator memberships must be agreed; IAM currently grants non-owner members only Read. |
| `IEdgeGatewayAuthenticator` | IoTAssets or Iam (to be decided) | Verifies gateway credentials and returns the gateway and the ranch it serves. No gateway credential scheme exists yet. |
| `ICattleLookup` | CattleInformation (Giorgio) | Animal ranch, incorporation time and deactivation time; lot membership in a ranch. |
| `IDeviceAttributionLookup` | IoTAssets (Alison) | Device owner and the assignment effective at a capture instant. |

## Host integration

This branch does not change `Program.cs`, `Shared`, project files, global configuration, the shared DbContext or migrations.

1. Register the shared PostgreSQL DbContext and expose the same scoped instance as `DbContext`.
2. Apply `OperationsMonitoringEntityConfigurations` through `ApplyConfigurationsFromAssembly` and generate the shared migration centrally. Tables use the `monitoring` schema: TelemetryReadings, MonitoringAlerts, AlertEvidence, AlertChanges, Geofences, GeofenceVertices, MonitoringThresholds, MonitoringRuleSets and LivestockOperations.
3. Register real implementations of the four ports, then call `builder.Services.AddOperationsMonitoring(builder.Configuration)`.
4. Optionally configure `OperationsMonitoring:ClockSkewTolerance`, `OperationsMonitoring:MaximumBatchEntries` and `OperationsMonitoring:MaximumPageSize`.

## Pending scope

The following requirements are not implemented here because their contracts or upstream data do not exist yet:

- TS-15 configuration aggregate: device assignments, animal life stages and local authorizations must be composed with IoTAssets, CattleInformation and Iam. This module publishes only its own rules at `monitoring-rules`.
- TS-18 `field-snapshot`, which depends on CattleInformation records, and base-version conflicts for animal files.
- TS-11 notifications, US-18 reproductive indicators, US-40 and US-42 treatment-response evaluation, US-41 withdrawal periods (owned by Planning), US-24 and US-48 aggregated clinical views, and the water controller stories US-54 to US-57, TS-13 and TS-14.
- Recording denied access attempts (US-14) belongs to Iam.

## Verification

The solution builds with the existing package versions. A temporary xUnit project outside the repository, so that no project is added to the solution, exercised:

- Domain rules: measurement validity, staleness, polygon validation, threshold evidence, the six-hour window, attention idempotency and versions, and geofence returns.
- Application services through EF Core on in-memory SQLite: per-entry batch results, duplicates and conflicts, attribution without assignment, clock tolerance, alert deduplication and replays, Edge and cloud attention conflicts, authorization denials, telemetry absence and staleness, field-operation rules, and rule revisions.
- The PostgreSQL model and generated DDL through Npgsql, without a server.
- HTTP routes on an in-process test server with dependency validation, using test-only port doubles.

PostgreSQL behavior that SQLite cannot reproduce (unique-violation translation, repeatable-read snapshots and concurrency tokens under load) and the real adapters remain integration checks.
